# Project context: Freight Dispatch Simulator

Context for developers and AI assistants working on this repo. Keep it short and current.

## Purpose

A **showcase** project, not a production library. It favours a small, readable model
and honest, reproducible numbers over features.

## Core design decision: one model, one evaluator

Every method follows the same execution rules (see `SOLUTION_APPROACHES.md` §2) and
is scored by replaying its assignment in the discrete-event simulation
(`evaluate_assignment`). Never add a method whose numbers come from a different model.

- `src/schedule.jl`: execution rules (`plan_trip`, `commit!`), the analytic
  evaluator `evaluate_plan` and `kpis`. The tests check that it matches the simulation.
- `src/simulation.jl`: ConcurrentSim simulation. It uses `QueueStore` (FIFO); a plain
  `Store` is unordered. There is no global state, and results come from the vehicle processes.
- `src/strategies.jl`: greedy rules via `choose_vehicle`. Ties go to the lowest
  vehicle index, so runs are deterministic.
- `src/LocalSearch.jl`: relocate and swap moves, scored with `evaluate_plan`.
- `src/MILPOptimizer.jl`: exact model of the same rules. FIFO order per vehicle is
  fixed, so sequencing reduces to pairwise big-M precedence. The greedy solution is
  used as a warm start.
- `src/experiments.jl`: `compare_methods`, `generate_instance`.
- `src/MapVisualization.jl`, `src/Replay.jl`: standalone plotly.js HTML (CDN); `src/Timeline.jl`: SVG Gantt.
  No Plots/PlotlyJS dependency.

## Conventions

- Inputs: DataFrames or a directory with `freights.csv` and `vehicles.csv`; they are
  never modified. `pickup_time` = release, `delivery_time` = deadline (seconds or DateTime).
- Results: `DispatchResult` (`freight_results`, `vehicle_aggregates`, `kpis`, `info`).
- Objective: `ObjectiveWeights` (km + 100 per hour late + 10 000 per unserved freight).
- `Simulation(f, v, strategy)` is kept as a convenience wrapper; the 4-argument form
  with a time buffer is deprecated.
- Blue style formatting (`.JuliaFormatter.toml`); `Manifest.toml` is not committed.

## Workflows

- Tests: `julia --project=. -e 'using Pkg; Pkg.test()'` (about 1–2 min, includes MILP solves).
- Benchmark: `julia --project=. scripts/benchmark.jl` regenerates `docs/BENCHMARK.md` and the CSVs;
  update the summary table in `README.md` from it. `--quick` is for smoke tests (CI).
- Visuals: `julia --project=. scripts/render_visuals.jl` writes `docs/maps/*.html`,
  `docs/replay/iberia.html` and `docs/assets/timeline_iberia.svg`. The README GIF comes from
  `scripts/capture/capture_replay.js` (Playwright) + `scripts/capture/make_gif.py` (Pillow).
  Chart colours follow a validated light/dark palette; status red/green only mean late/on time.

## History

- v0.1–0.2: SimJulia simulation plus a separate MILP and local search. The MILP used a
  different model (cumulative capacity, no time), so its "optimality gap" was not meaningful.
- v0.3 (2026-09): single evaluator; MILP and local search rewritten to the simulation's
  rules; deadlines and lateness; queueing instead of rejecting when all vehicles are busy;
  ConcurrentSim; no global state; benchmark script; CI.
